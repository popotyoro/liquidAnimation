## 粒子方式で扱っていた表現を再導入する

今回の簡略化で省いた表現を、将来の対応候補として残す。以前の試作では、粒子を個別に動かし、複雑な液体形状を扱っていた。ただし、玉状の見た目や過剰な跳ね返り、水位誤差があり、完成した液体表現には至っていなかった。

- [x] 着水時に水面から飛び出す飛沫を表現する（重力で落下し、水面に再吸収する小規模な飛沫）。
- [ ] 水流から分離した水滴が重力で落ち、たまった水へ戻る動きを表現する。
- [ ] 水面が盛り上がるだけでなく、巻き返る・砕けるなどの複雑な形状を扱う。
- [ ] 液体内部の局所的な流れや渦を含む、2Dの流体計算を再検討する。

現在の「指定量で止まる」「平均水位が指定量に合う」「注水後に静まる」を維持すること。独立した水滴や飛沫も総量に含め、玉が跳ね続ける挙動に戻さない。現在の水面計算に小規模な飛沫を組み合わせた。水流にも描画上のうねりと太さの変化を追加したが、水流からの分離や巻き返りは未対応。全面的な流体計算が必要かは表現と負荷を比較して判断する。

## 数値計算ライブラリの活用

以下の3候補を記録する。いずれも流体シミュレーション一式を提供するものではなく、計算の実装・高速化を補助する。現時点では追加していない。

| 候補 | 提供形態・用途 | このプロジェクトでの検討内容 |
| --- | --- | --- |
| [MLX Swift](https://github.com/ml-explore/mlx-swift) | SPM対応。多次元配列の演算、CPU/GPU実行。iOS対応 | 2D格子へ拡張する際に、近傍セルの更新や圧力の反復計算を試作する候補。流体方程式・境界条件・水量保存は別途実装する。 |
| [Swift Numerics](https://github.com/apple/swift-numerics) | SPM対応。複素数や汎用的な数値型・数学関数 | 必要な数学処理が増えた場合の補助。現在の浅水モデルを置き換えたり、GPUへ移したりするものではない。 |
| [Accelerate](https://developer.apple.com/documentation/accelerate) | OS標準フレームワーク。SPM追加は不要。CPUでの配列・行列演算を高速化 | `vDSP`・`vForce` による配列演算や数学関数の一括処理を検討する。現在の128列程度で効果が出るかは実測する。 |

MLXはAppleの機械学習研究チームが開発するOSSで、GitHubの公開組織は `ml-explore`。[Apple公式のOpen Sourceサイト](https://opensource.apple.com/projects/mlx/)にも掲載されている。Appleは[WWDC26の数値計算セッション](https://developer.apple.com/videos/play/wwdc2026/328/)で、MLX Swiftによる2D格子の熱分布計算などを紹介している。流体への適用は、このプロジェクトでの検討案である。

- [ ] 2D流体計算を試す段階で、MLX Swiftと直接Metalで計算する方式の実装量・負荷を比較する。
- [ ] CPU計算がボトルネックになった場合、Accelerateを使う箇所を計測結果から選ぶ。
- [ ] 複素数や汎用数値型が必要になった場合、Swift Numericsの採用を検討する。

採用前に、実機でフレーム時間・CPU/GPU時間・メモリ使用量を比較する。追加するだけで高速化・高品質化すると判断せず、指定量で止まること、水量保存、注水後の減衰、Swift 6の並行性チェックを維持する。
