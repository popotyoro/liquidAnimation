# 液体注入アニメーション仕様書

最終更新: 2026-10-18。現在の作業ツリーにある実装を対象とする。今後の候補は[将来対応リスト](future-features.md)を参照。

## 目的と表示

任意の画面を長方形の容器に見立て、上端の一か所から液体を斜めに注ぐ。文字・画像・ボタンは障害物として扱わず、水のレイヤーを重ねる。背後の画面は透けて見え、タッチ操作を妨げない。

- SwiftUI の iOS アプリ。最低対応バージョンは iOS 27.0。
- 正面から見た2D表示。重力は画面下向きに固定する。
- 量と不透明度を0〜100%で設定できる。
- 連続した水流、着水時の飛沫・気泡と波、横への広がり、注水後の減衰を表現する。
- 最近の iPhone で60fpsを目標とする。達成の判断には実機測定を使う。

## 液量は空中の水も含めて管理する

%は容器の容量に対する投入総量を表す。空中の水流・飛沫も投入量に含め、目標に達した時点で流入を止める。その後、空中にある分が着水して水面が落ち着くと、50%なら容器の中央が平均水位になる。

一定の奥行きを仮定し、2D断面の面積で管理する。容器の幅を `W`、高さを `H`、水深を `h(x)` とすると、容量と保存する量は次のとおり。

```math
A_{capacity}=WH,\quad
A_{emitted}=A_{jet}+A_{spray}+A_{pool},\quad
A_{pool}=\int_0^W h(x)\,dx
```

気泡は空気を表す装飾で、水の面積には含めない。気泡による水面の押し上げも計算しない。

目標量を超えて追加しない。水面の波で局所的に中央を超える場合も、平均水位と投入量を区別する。境界での丸めやクリップによる誤差は、水深を0〜Hに保つ補正で取り除く。

## 設定と操作

| 項目 | 範囲・初期値 |
| --- | --- |
| 種類 | 水・ビール・炭酸水・粘度のある水。初期値は水 |
| 色 | 種類の標準色・ブルー・アンバー・グリーン・ピンク。初期値は種類の標準色 |
| 目標量 | 0〜100%、初期値50% |
| 不透明度 | 0〜100%、初期値45%。0%では水を表示しない |
| 注ぐ位置 | 上辺の15〜85%、初期値25% |
| 注ぐ角度 | 鉛直下向きが0°、−65〜65°、初期値30°。正の値は右向き |
| 流量 | 毎秒、容量の2〜16%。初期値8% |

「注ぐ」で空の状態から指定量まで注ぐ。流量設定は最大流量を表し、開始・終了時は滑らかに増減する。一時停止・再開・空に戻す操作を用意する。色と不透明度は即時反映し、種類・目標量・注ぎ方は次の注水から適用する。種類の選択だけで進行中の注水をリセットしない。注水終了後も水面の計算を続ける。画面サイズが変わった場合は空に戻す。

試作画面には透過を確認する文字・図形・ボタンを配置する。操作パネルを重ねても液体の描画領域を縮めない。

## 液体の種類と色

種類は`FluidKind`、内部の近似係数は`FluidMaterial`、色の選択は`FluidColorChoice`、描画用の配色は`FluidPalette`で扱う。種類は注水開始時にコピーし、色だけ変えても投入量・軌道・水面・気泡の状態は変えない。色を「種類の標準色」にした場合、現在注水している種類に従い、ビールはアンバー、それ以外はブルーを使う。明示的に選んだ色は種類を変更しても保持する。

| 種類 | 運動量の減衰係数（毎秒） | 初速 | 飛沫量・上昇速度の倍率 | 気泡 |
| --- | --- | --- | --- | --- |
| 水 | 2.8 | 1.6m/s | 1 | 着水時のみ。半径2〜6mm、発生間隔45ms以上 |
| ビール | 3.2 | 1.6m/s | 0.8 | 着水気泡の半径は水の65%。加えて80ms以上ごとに水中の1点から発生 |
| 炭酸水 | 2.8 | 1.6m/s | 1 | 着水気泡の半径は水の50%、発生間隔25ms以上。加えて35ms以上ごとに水中の1点から発生 |
| 粘度のある水 | 18 | 1.1m/s | 0.04 | 着水気泡の半径は水の75%、発生間隔150ms以上 |

粘度のある水は、着水圧力を水の35%、水流のうねりと太さの変動を18%に抑え、注ぎ終わりの帯を水滴へ分離しない。減衰や飛沫を調整して粘りを近似するもので、粘性応力・付着・糸引きを解くモデルではない。指定量・設定した最大流量・注水時間の定義は全種類で共通。

ビールと炭酸水の水中気泡は、水深3.5cmを超える位置で、幅の8〜92%の範囲から発生ごとに異なるX座標を選ぶ。発生位置は底の近くとし、高さ・大きさ・揺れの位相にもばらつきを与える。発生番号と用途を種にした決定的な疑似乱数を使い、再注水で同じ並びを再現できる。半径は`(5〜10mm)×種類の半径倍率`、上昇速度は`0.18＋半径×16`（m/s）。寿命は`発生時の水深÷上昇速度＋0.6秒`とし、水面へ届く前に消えるのを抑える。着水気泡と同じ最大128個の枠を使い、水量・運動量に影響させない。注水終了後も生成を続け、一時停止中は生成・移動とも止め、リセット時は発生状態も消す。炭酸気泡の表示直径は画面幅の最低1.2%を確保する。これは視認性のための描画上の近似で、水量を変えない。炭酸気泡だけ輪郭を太めにし、合成に使う不透明度を`1−(1−設定不透明度)^1.8`にする。不透明度0では気泡も完全に消す。溶存ガスの減少は未対応。

細かな物性や色の数値を編集するUIは設けず、まずプリセットとカラーバリエーションで違いを確認する。以下の物理定数・飛沫・気泡の数値は、特記がなければ水プリセットの基準値を示す。

## SwiftUIからの利用

任意のViewへ `.liquidOverlay(controls:ignoresSafeArea:)` を適用する。操作状態は呼び出し側が保持し、再描画のたびに作り直さない。

```swift
@State private var controls = FluidControls()

var body: some View {
    DemoBackground()
        .liquidOverlay(controls: controls, ignoresSafeArea: true)
}
```

`ignoresSafeArea` の既定値は `false`。通常は適用先の領域に重ね、`true`なら液体レイヤーだけをセーフエリアまで広げる。背景のレイアウトサイズは変更しない。デモでは画面上端から注ぐため `true` を指定する。

`View`拡張は内部の`LiquidOverlayModifier: ViewModifier`を呼び出す入口とする。重ね合わせ、セーフエリア、タッチの透過、アクセシビリティからの除外はこのmodifier内で設定する。`LiquidOverlay`はモジュール内部の実装とし、利用側での`ZStack`や`.overlay`の指定は不要。現在はアプリ内のAPIであり、別パッケージ向けの`public`宣言は行っていない。

## 落下水流と浅水モデルを組み合わせる

粒子方式の試作で生じた玉状の輪郭、強い跳ね返り、水位誤差を改善するため、現在は**重力による落下水流と、連続した水面の計算**を組み合わせる。液体内部の渦を含む2D Navier–Stokes方程式を全面的に解く方式とは異なる。

### 落下水流

初速と重力から軌道を計算する。細かい時間区間ごとに投入時刻と量を記録し、軌道が水面または底に達した分を容器内の水へ移す。壁では外へ抜けず、壁沿いに下へ流す。壁から弾性反射させない。

```math
x(t)=x_0+v_{x0}t,\qquad
y(t)=v_{y0}t+\tfrac12gt^2
```

描画は一続きの帯とする。流量を `Q`、落下速度を `|v|` とし、帯の幅は `Q/|v|` を基準にする。加速すると細くなり、流量の増減は投入時刻の履歴に沿って上流から下流へ伝わる。

- 入口は画面上方まで延長し、画面内に斜めの切断面を見せない。
- 水面まで2cm未満に近づいた先端は、最大約33ms分だけ軌道を延長して描き、着水点の隙間を抑える。
- 開始・終了時は最大0.25秒かけて流量を増減する。最後は上側から細くなって切れ、残った水が落ちる。
- 最初の水が水面付近へ達するまでは、初期投入量に応じた半径最大2cmの丸い先端を描く。手前の細い区間もつなぎ、増流区間の後半で幅の補正を0へ戻す。

帯は基本97断面に、流量の増減区間で最大24断面、丸い先端で17断面を加える。各断面の左右2頂点で帯を作り、分離前は最大276頂点とする。先端の丸みと幅の補正は描画上の近似で、水量や着水判定は元の軌道で計算する。

最大流量を `Q`、目標面積を `A` とすると、増減時間は `r=min(0.25, A/Q)`、注水時間は `T=A/Q+r`。増加区間は `Q(3u²−2u³)`（`u=t/r`）、減少区間はその時間反転を使う。面積はこの関数の解析的な積分で求め、細かい時間刻みでも総量を指定値に合わせる。少量指定では増加区間と減少区間がつながる。

投入時刻に応じた二つの正弦波で帯を揺らし、太さも変える。変形は落下中に育つ描画上の近似であり、乱流や表面張力を解いてはいない。液量と着水位置の判定には元の放物軌道を使う。

### 小さな試作: 注ぎ終わりの水滴への分離

注水停止から50ms後、減流区間の最後の40%に相当する未着水の水を、投入時刻で最大3組にまとめて水滴へ移す。各組の面積は合計値、位置と速度は面積で重み付けした投入時刻の落下軌道から求める。水流から同量を取り除き、投入総量・着水済み量は変えない。

水滴は既存の飛沫と同じ上限96滴の範囲で扱い、重力で落下して水面へ吸収する。計測上の飛沫の量には分離した水滴も含む。帯の描画は分離した部分を再びつながず、残った末尾を丸く閉じるため最大12断面を追加する。帯全体の上限は300頂点。

対象となる区間が3個未満の場合や、水滴の空き枠が足りない場合は元の水流のまま落とす。満水近くですでに着水した分は分離しない。これは表面張力を解かない一回限りの試作で、注水中の分裂・水滴の合流・砕波は未対応。

### 着水時の飛沫と跳ね返り

着水点に水深と上方の空間がある場合、最大約40回/秒、各2滴の飛沫を出す。その時間刻みの着水量の32%を飛沫へ振り分け、残りを水面に加える。飛沫は投入量に含まれ、追加の水は生成しない。飛沫の同時数は最大96滴。上昇速度は最大1.15m/s（静止水面から約6.7cm上昇）に制限する。

飛沫は重力で落下し、壁では水平速度を15%に減らして反射する。落下中に水面に触れると全量を戻し、再び飛び出させない。描画は速度方向に伸ばした楕円とし、面積を保ったまま縦横比を変える。着水時には水面へ外向きの運動量を加えて波を作る。これらは見た目と計算量を調整した近似で、厳密な飛沫生成モデルではない。

### ビールの水面に残る泡

ビールだけ、注ぎ始めは泡が多く、排液につれて下の液体が増える層を描く。[日本ビアジャーナリスト協会の記事](https://www.jbja.jp/archives/57114)にある、泡の膜から液体が戻る説明を参考とする。以下の係数は記事の測定値ではなく、短いアニメーションで変化を見せるための近似。

着水済みの液体面積`A`の内数として、泡に保持される液体面積`F`を管理する。着水増分`ΔA`に対する保持率は`0.12＋0.78×exp(−着水済み割合/0.08)`とし、開始直後の約90%から徐々に12%へ下げる。毎ステップ`F ← min(A, F×exp(−Δt/6秒)＋ΔA×保持率)`で排液する。`F/0.40`を表示用の白濁域の面積へ変換する。泡は既存の液面より内側に限定し、泡が減ると下の液体との境界が上がる。ガスによる液面より上への膨張は描かない。

浅水計算は従来どおり着水済み全量の水深で行い、描画時に、平均液深から`F/(0.40×W)`を引いた高さを泡と液体の境界とする（`W`は容器幅）。局所的な上端の起伏は境界の計算へ使わず、上下に同じ凹凸を複写しない。境界は独立した弱い起伏と泡厚の16%の遷移幅でぼかす。白濁域は底でクリップする。上端は幅方向に約5個の大きな丸い起伏と、弱い細かな起伏を組み合わせ、元の液面から内側へ最大で画面幅の2.6%だけ変形させる。変形量は泡の厚さと液深でも制限し、薄くなると消す。水本体と気泡のクリップにも同じ輪郭を使う。液体との境界の凹凸と不規則な細胞模様を加え、不透明度は`1−(1−設定不透明度)^2.8`とする。0では完全に消す。保持量は既存の着水量の内数なので、投入総量へ二重加算しない。最終的には指定量の液体へ戻る。

参考動画：[けんた食堂「ビールの注ぎ方」](https://www.youtube.com/watch?v=xj6CQxJONCI)。12秒付近の全体の白濁、17〜22秒付近の下側の透明化、47〜57秒付近の泡の質感と大きな丸い上端を、Computer Useで確認した。動画中には待ち時間の説明があるため、動画の経過秒数を実時間の物理係数には使わない。

上に残る泡とは別に、液中の微細気泡による白濁度`C`（0〜1）を持つ。毎ステップ`C₀=C×exp(−Δt/2.4秒)`、`E=1−exp(−ΔA/(容器容量×0.025))`、`C=C₀＋(1−C₀)×E`で着水による巻き込みと透明化を近似する。平均水面高さ`h`に対し、透明化する高さを`h×(1−clamp(1.15C,0,1))`とし、広い遷移幅で下から黄白色の濁りを抜く。上の泡はクリーム色、液中の濁りは黄みを残す。均一な細胞模様の強度を抑える。白濁は体積・運動量を変更せず、一時停止で止まり、リセットで消える。

泡の局所的な輸送、気泡の合体・破裂、溢流は未計算。画面外の泡はクリップする。一時停止中は排液と模様の時間を止め、リセット時に保持量をゼロにする。

### 巻き込まれて浮上する気泡

気泡は水と空気を同時に解く物理モデルではなく、着水感を補う装飾として扱う。水深が3.5cmを超え、投入時刻の流量が設定した最大流量の5%を超える着水点で、45ms以上の間隔で2個ずつ発生させる。同時数は最大128個、半径は2〜6mm、寿命は1.8〜2.8秒。浅い場所、ほぼ流量がゼロのときは生成しない。

着水直後は下向きに動き、抵抗で減速して上昇へ移る。水平方向は水面モデルの流れの一部と正弦波で揺らす。水面・底への接触または寿命で消し、出現時と消失前には濃さを変える。水の量・水深・運動量には影響させず、気泡の合体・分裂・圧縮は扱わない。

Metalでは透明な中心、明暗のある縁、小さな反射光を描く。水面より上はシェーダーでも切り抜く。水面の傾きに応じた明暗と、着水圧力に連動して動く淡い水中模様も加える。模様は圧力の減衰とともに消え、実際の内部の渦や背景の屈折を表してはいない。

### 容器内の水

垂直方向を平均化し、水平1次元の浅水方程式で水深 `h` と流量 `q=hu` を計算する。`u`は横方向の速度、`g`は重力加速度。

```math
\frac{\partial h}{\partial t}+\frac{\partial q}{\partial x}=s_h,\qquad
\frac{\partial q}{\partial t}
+\frac{\partial}{\partial x}\left(\frac{q^2}{h}+\frac12gh^2\right)
=s_q-\gamma q-h\frac{\partial P}{\partial x}
```

着水量をガウス分布で周囲の列へ加え、横への広がりと波を計算する。同じ時間刻みの着水判定は、すべて更新前の水面を参照する。直前に加えた水によって後続の水流が連鎖的に着水する不具合を防ぐ。

投入先の分布は、標準偏差を `max(1.5Δx, 0.45Q(t_emit)/v_y)` とする。`Δx`は列の幅、`v_y`は着水時の鉛直速度。満水近くで遅く・太くなる水流を固定幅へ集中させない。壁際では分布の重みを正規化し、加える量を保つ。

落下水流の鉛直運動量から外部圧力 `P=p/ρ` を近似し、水面を押し下げる力 `−h ∂P/∂x` を運動量へ加える。これにより中心がへこみ、両脇が盛り上がる。水深を直接削らず、水の移動で形を変える。

| 計算項目 | 現在の近似 |
| --- | --- |
| 着水圧力の分布 | ガウス分布。標準偏差は `max(2.5Δx, 0.65Q_max/v_y)` |
| 圧力の大きさ | 各時間刻みの着水面積×鉛直速度をもとに計算。結合係数0.12、水頭上限6cm |
| 圧力の応答 | 時定数60ms。着水が止まると減衰する |
| 着水の水平運動 | 水流の水平速度と、鉛直速度の30%を基準にした外向きの力を近似的に追加 |
| 運動量の減衰 | `exp(−2.8Δt)`。水平速度は±2.5m/sに制限 |
| 壁 | 反射境界。壁を通る液量は0 |

128列の有限体積法と Rusanov flux を使い、CFL条件に応じて時間刻みを分割する。容器の幅は0.75m、重力は9.81m/s²、初速は1.6m/sと仮定する。モデルへの1回の入力は最大1/30秒、内部の時間刻みは最大1/240秒かつCFL係数0.4で制限する。描画ループは1フレーム最大1/60秒だけモデルを進め、大量の追いつき計算は行わない。

波の巻き返り、砕波、大量の独立した飛沫、気泡と水の相互作用、厳密な粘性・表面張力は対象外。水面は各水平位置につき一つの高さで表す。これは軽さと安定性を優先するための、合意済みの簡略化である。

## SwiftUI・CPU・Metalの役割

物理計算はSwiftでCPU上に実装し、MetalはGPU上で描画を行う。現在はMetalの計算シェーダーや、MLX・Swift Numerics・Accelerateを使用していない。

Fluid内は、SwiftUIとの接続を`View/`、設定と状態のデータ型を`Model/`、計算と再生制御を`Simulation/`、GPUへの転送と描画を`Rendering/`に分ける。`WaterModel`は水深などの更新を実行するため`Simulation/`に置く。下表のFluid内のパスは、このディレクトリを基準とする。

| 担当箇所 | 責務 |
| --- | --- |
| `ContentView.swift` / SwiftUI | 背景画面、設定、注水・停止・リセットの操作 |
| `Model/FluidConfiguration.swift` | 注水設定と範囲補正 |
| `Model/FluidKind.swift`・`Model/FluidMaterial.swift`・`Model/FluidColorChoice.swift` | 種類、内部の近似係数、色の選択 |
| `Model/FluidControls.swift` | 操作要求と表示用の状態・計測値 |

色や光沢の変更は主に`Rendering/Fluid.metal`、水流の形状はSwift側の描画データ生成、粘りや波など動きの変更は物理モデルで扱う。色はパレットを介して浅部・深部・水流・飛沫へ適用する。光沢の形と強さは全種類で共通。SwiftとMetalの`WaterUniforms`は7個のfloat4、112バイトで配置を揃える。最後のfloat4は泡の描画設定で、xに画面幅基準の泡の厚さ、yに液中の白濁度、zに高さ基準の平均液深を渡す。

水面には細い明るい縁と、その下へ減衰する幅のある反射光を描く。左上に広い光源があると仮定し、水面の傾きで反射の強さを変える。水中には広い淡い濃淡、水流には断面方向の陰影と細い光沢、水滴には局所的な反射光を加える。いずれも描画上の近似で、背景の反射・屈折や光の物理計算は行わない。不透明度と液量は変更せず、追加の描画パスやテクスチャは使用しない。

溜まった水の上端には、壁際で持ち上がるメニスカスと、着水圧力に応じた細かい波を描画時に加える。壁際の持ち上がりは画面幅の最大0.75%、細かい波は最大0.25%を基準とし、空・満水に近づくと消す。持ち上がりの平均を引いて水位の偏りを抑えるが、表示上の輪郭は物理モデルの水位とは異なる。細かい波は着水圧力とともに減衰し、一時停止中は動かない。傾きで途切れる反射光で上端の丸みを表す。水面直下に輪郭をなぞる暗い線は付けない。着水点の両側には、着水圧力に応じた小さな肩状の盛り上がりを描画上で加える。毎秒2.1周期、半周期ずらした2つのパルスを重ね、正規化年齢`a`（0〜1）に対し距離`0.018＋0.080a`、幅`0.010＋0.020a`（ともに画面幅基準）のガウス形を左右へ移す。振幅の係数は画面幅の3.5%×圧力強度×`sin²(πa)`。着水中心では変形をゼロにし、水流との接続を保つ。空・満水付近の抑制を共用し、圧力が消えると変形も消す。液量はCPUの水深・水流・飛沫で従来どおり管理する。これは着水の視覚的な近似で、巻き返り・砕波・局所輸送の物理計算ではない。気泡のクリップも同じ表示用水面を使う。表面張力の計算や画面外への流出は行わない。

描画順は水流→容器内の水→気泡→ビールの表面の泡→飛沫。水面より下の水流を容器内の水で覆い、気泡は水面より上を切り抜く。各パスは透明な描画先へalpha乗算済みの色を合成する。

`MTKView` を `UIViewRepresentable` で組み込む。毎フレームの水面データを SwiftUI の状態へ渡さず、計測表示は約0.5秒ごとに更新する。注水コントロールバーには、操作ボタンの下に描画頻度（fps）、GPU時間（ms）、物理計算のCPU時間（ms）を表示する。横幅に収まらない文字サイズでは縦並びに切り替える。計測値は設定画面には置かない。

UI、水面モデル、CPUによる描画バッファの変更はMainActor上で行う。Metalの完了通知からは計測値とエラー文字列をMainActorのタスクへ渡す。前のGPUコマンドが完了するまで次のフレームのバッファ更新を待ち、CPUとGPUによる同時アクセスを防ぐ。

背景をゆがめる屈折には背景画像を渡す設計が必要なため、初期版では扱わない。

## 処理負荷の改善と測定

実機で水・ビールとも途中から約30fps、GPU約10ms・CPU約14msという報告があった。機種・ビルド条件を含む実機での改善効果は再測定する。

- CPUの流束計算では、ある面の右セルの水深・流速・波速を次の面の左セルへ引き継ぎ、除算と平方根の重複を減らす。CFL条件、刻み、格子数は変えない。
- 注水の水平・鉛直初速はリセット時に一度計算する。液量の一様補正が上下限に触れない場合は直接求め、乾いた列・満水付近などのクリップが必要な場合は従来の二分探索を使う。
- 表示用の水面と傾きはMetalの`prepareWaterSurface`で横一列だけ事前計算し、水・泡・気泡で共有する。サンプル数は描画幅のピクセル数、最大4096。高さ・傾きのfloat2配列を線形補間する。4096pxを超える幅では補間の間隔が広がる。物理ソルバーはCPUのまま。
- 表示水面の計算と描画は同じGPUコマンドバッファで順に実行する。スレッドは`dispatchThreadgroups`で固定幅のグループに切り上げ、余剰分をkernelの範囲チェックで除く。非一様スレッドグループが未対応の環境でも動作する方式を使う。GPU使用中の共有バッファをCPUが書き換えない制約は維持する。同時進行は従来どおり1フレームで、複数バッファによるCPU/GPUの並行化は未実施。

全103件のテストが成功した。性能改善後の実機FPSは未確認。非一様スレッド起動によるアプリのMetal検証エラーを修正した。テスト成功に加え、通常起動後のコンソールとプロセス状態も確認する。

`FluidPerformanceTests`は投入量80%・流量16%/秒で、水とビールの1〜2秒・3〜4秒・6〜7秒の物理計算と描画転送の平均時間をログへ記録する。固定時間以内という合否基準は設けない。同じiPhone 18 ProシミュレータのDebug条件で、ビールの3〜4秒の物理計算は変更前約6.61ms、CPU変更後の一測定では約6.00msだった。シミュレータの測定値を実機性能や安定した改善率とは扱わない。

CPU変更のみでは13時点の描画画像が変更前と完全一致した。表示水面の事前計算も加えた後は、400×864pxの各画像で変化した色チャンネル数は0〜7個、最大差は6/255で、目視でも形状を確認した。実機の高解像度でのGPU時間とFPSは別途確認する。

## 今後の検討範囲

気泡の合体・分裂、注水中に水流から分離する水滴、砕波、内部の渦、触覚フィードバックは未対応。[将来対応リスト](future-features.md)で管理する。

物理計算のGPU化と数値計算ライブラリの導入も検討段階にある。現在の128列の浅水モデルを移すだけで画質が改善するとは判断せず、2D流体モデルへ進む際に実装量・性能・水量保存を比較する。
