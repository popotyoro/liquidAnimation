# 液体注入アニメーション仕様書

## 目的と確定要件

任意の画面を長方形の容器に見立て、上部の一か所から液体を斜めに注ぐ。元の画面にある文字・画像・ボタンを障害物として扱わず、液体を独立したレイヤーとして重ねる。

- iOS アプリを SwiftUI で作成する。現在のプロジェクトの最低対応バージョンは iOS 27.0。
- 正面から見た **2D** の液体を扱う。奥行き方向の流体計算は行わない。
- 重力は画面下向きに固定する。初期版では端末の傾きに追従しない。
- 投入する量を 0〜100% で指定する。0% は空、100% は容器を満たす量とする。
- 液体の透明度を設定でき、背後の画面がある程度透けて見える。
- 落下・着水・飛沫・水面の波・注入後の揺れを物理計算で表現する。
- 最近の iPhone で **60fps を目標**とする。達成の判断には実機測定を使う。

## 液量と注水の扱い

% は瞬間の水面の高さではなく、容器の容量に対する投入量の割合を表す。空中の水流や飛沫も投入量に含め、指定量を投入した時点で流入を止める。静止後の平均水位が指定割合に対応する。

2D では奥行きを一定と仮定し、液量を断面積で管理する。粒子数と粒子一つの面積から投入量を求め、最後の投入数を制限する。数値計算の解像度による水位誤差は残るため、粒子単位の量と静止時の水位を別々に検証する。

初期版は毎回空の状態から指定量まで注ぐ。注水を止めた後も計算を続ける。一時停止・再開・空に戻す操作を用意する。実行中の目標量・流量・角度・注ぎ口位置の変更は次の注水に適用し、透明度は即時反映する。

## 設定項目と試作画面

| 項目 | 初期版の扱い |
| --- | --- |
| 目標量 | 0〜100%、初期値 50% |
| 不透明度 | 0〜100%、初期値 45%。0% なら液体は不可視 |
| 注ぐ位置 | 上辺の左右方向。壁との干渉を避ける範囲に制限 |
| 注ぐ角度 | 鉛直下向きを 0° とし、左右へ変更可能 |
| 流量 | 1 秒に投入する容量の割合 |

試作画面には、透過を確認するための文字と図形、設定画面、注水・一時停止・リセット操作を置く。液体レイヤーはタッチを遮らず、背後の画面を操作できるようにする。

## 物理計算の実装案

**第一候補は APIC と格子上の圧力投影を組み合わせた流体ソルバー。** 粒子で液体の位置と量を保持し、格子で速度と圧力を求める。実装・検証の結果に応じて解像度、反復回数、時間刻みを調整する。

基礎式は非圧縮性流体の Navier–Stokes 方程式と連続の式とする。

```math
\frac{D\mathbf{u}}{Dt}=-\frac{1}{\rho}\nabla p+\nu\nabla^2\mathbf{u}+\mathbf{g},
\qquad \nabla\cdot\mathbf{u}=0
```

`u` は速度、`ρ` は密度、`p` は圧力、`ν` は動粘性係数、`g` は重力加速度。最初の試作では非粘性モデルを基礎に、数値的な減衰を使用する。粘性・表面張力・空気との相互作用を厳密に解くことは初期版の保証範囲に含めない。

計算の流れは「粒子の追加 → 粒子から格子への速度転送 → 重力 → 圧力投影 → 格子から粒子への速度・局所速度勾配の転送 → 粒子の移動」。圧力投影では次を離散化する。

粒子移動や注ぎ口での粒子配置により生じる圧縮誤差は、基準粒子密度を超えた分を圧力計算の右辺に加えて補正する。これは数値的な体積維持の補正であり、厳密な物性モデルとは区別する。

```math
\nabla^2p=\frac{\rho}{\Delta t}\nabla\cdot\mathbf{u}^{*},
\qquad \mathbf{u}^{n+1}=\mathbf{u}^{*}-\frac{\Delta t}{\rho}\nabla p
```

左右と底は液体が通過しない壁とする。試作では粒子を容器内に保持し、100% 時にも粒子を失わないよう上端にも境界を置く。上端からあふれる表現は対象外。自由表面は大気圧を基準とし、時間刻みを分割して高速な粒子の移動を抑える。

## SwiftUI と Metal の役割

SwiftUI は設定・操作・背景画面を担当する。Metal は物理計算と、粒子から連続した液面を再構成する描画を担当する。`MTKView` を `UIViewRepresentable` で組み込み、透明なレイヤーとして合成する。

半透明の着色と水面のハイライトを先に実装する。背景をゆがめる屈折は、背景内容を画像・テクスチャとして渡す追加設計が必要なため、初期版の対象外とする。

## 検証と完了条件

- 0%、50%、100% で投入粒子数が目標に一致する。追加投入は目標数で止まる。
- 粒子が容器外へ漏れず、位置・速度・圧力に NaN や無限大が発生しない。
- 着水後に液体が横へ広がり、波が生じ、注水終了後に落ち着くことを確認する。
- 投影前後の速度の発散を比較し、圧力計算が非圧縮性の誤差を減らすことを確認する。
- 不透明度 0% では液体を表示せず、100% では背景が液体越しに透けない。
- 一時停止中は物理時間と投入量を保持し、リセットで空になる。
- 背景の操作、画面サイズ変更、アプリのバックグラウンド復帰を確認する。サイズ変更時は空に戻す。
- 実機で注水中・満水付近の CPU/GPU 時間、フレーム間隔、発熱を測る。シミュレータの結果だけで 60fps 達成とは判断しない。

## 試作の確認状況

現時点では操作確認用の試作。Xcode MCP で Swift と Metal のビルドを確認した。縮小した 24 列の計算格子では、0%・50%・100% の投入粒子数が目標数と一致し、容器外への漏れ・非有限値・粒子格納領域の超過は発生しなかった。

水位には圧縮誤差が残っている。同じ縮小格子で注水完了から約3秒後の重心から推定した水位は、目標50%で約47%、目標100%で約87%だった。これは液面の直接測定ではない。水位の精度、注水後に静まるまでの挙動、通常の64列格子での負荷、実機60fpsは引き続き検証する。

通常の描画では横64セル、1フレーム8分割、圧力計算40反復を使用する。容器の幅を0.75mと仮定して重力を換算し、粒子移動量と局所速度勾配に数値的な上限を置く。処理が遅れた場合は追いつくための大量計算を行わず、物理時間の進みを抑える。
